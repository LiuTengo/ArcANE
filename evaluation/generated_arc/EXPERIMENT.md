# Experiment protocol: character arcs in generated narratives

## 1. Research question and estimands

For story \(s\) generated by system \(g\) under condition \(d\), let
\(C_s\) be the set of evaluated principal characters and \(Y_{sc}\) be whether
character \(c\) has at least one qualifying arc axis. Report:

\[
R_{\text{char}}(g,d)=
\frac{\sum_s\sum_{c\in C_s}Y_{sc}}
{\sum_s |C_s|}
\]

and

\[
Q(g,d)=\operatorname{mean}_{s,c}\max_a \operatorname{score}_{sca}.
\]

Also report `story_arc_rate`, the fraction of generated stories with at least
one character arc. Rate and quality should not be collapsed into one number:
a system can produce arcs in a few vivid characters while leaving most
principal characters static.

## 2. Build the comparison set

1. Fix prompts, genre, requested length, language, sampling temperature,
   model revision, and decoding settings before collecting stories.
2. Compare at least two narrative systems or one system with/without an
   explicit arc-planning component.
3. Generate 3-5 independent samples per prompt and system. Treat samples as
   seeds, not independent source texts.
4. Include controls:
   - human-written stories as a high-reference diagnostic;
   - deliberately static character vignettes as negatives;
   - the same generated story with paragraph order shuffled as an ordering
     diagnostic;
   - a strong baseline and the proposed arc-aware system under matched
     prompts.
5. Do not tune thresholds or prompts on the final test split. Use a small
   development split for calibration.

## 3. Stabilize extraction

The extractor and judge should not share the same API call. First run:

```bash
python -m evaluation.generated_arc extract ...
```

The scored result uses extraction run 1 as the primary, pre-specified run.
`--extraction-runs 3` retains two extra passes as a recall/sensitivity audit;
extra axes are deliberately not pooled into the primary score because picking
the most favourable axis from multiple runs would inflate arc-presence rates.

Audit before scoring:

- every character name occurs in the story;
- every evidence quote is a verbatim substring of the cited span;
- an axis has at least two grounded phases;
- stable/no-change cases are represented instead of forcing an arc;
- no extractor imports outside canon or facts absent from the story.

If extraction recall is too low, improve the extractor prompt before the final
run or define a semantic merge/rule-of-two procedure in advance. Do not ask
the scoring judge to invent an axis that extraction missed, because that
changes the target from verification to open-ended interpretation.

## 4. Blind scoring

Run:

```bash
python -m evaluation.generated_arc run ...
```

For each grounded axis, the judge sees one generated story and one candidate
axis. Hide generator identity and condition. Randomize story and axis order
when calling the judge. Use temperature 0 and one fixed model revision.

The judge may reject the candidate because:

- the state is stable;
- change is only a mood or surface-style fluctuation;
- evidence is missing at one endpoint;
- the claimed change is an unexplained personality replacement;
- phase order or pacing contradicts the claimed trajectory.

`uncertain` never counts as positive. Invalid or ungrounded evidence is
retained in the extraction audit, but not used as positive proof.

If an ArcANE Stage 1 result already exists and the source narrative cannot be
sent whole, `score-arcane` can score the extracted dossier without source
text. Treat that as a secondary extraction-coherence analysis. It cannot
detect an arc that the extractor invented, and it must not replace the
source-grounded primary evaluation.

## 5. Aggregate with uncertainty

1. Pool axis records within character.
2. Use the highest-score qualifying axis as the character's arc strength.
3. Compute character arc rate only over evaluable characters; report
   non-evaluable coverage separately.
4. Compute story-level presence and quality.
5. Bootstrap at the prompt level, clustering all samples from the same prompt
   and system. Report 95% confidence intervals for paired system differences.
6. Report both macro averages over stories and micro rates over characters.
   Do not let a story with many detected characters dominate a macro claim.

## 6. Validate the judge

Use a stratified sample covering:

- generated and human-written controls;
- present, absent, uncertain;
- intrapersonal and relational axes;
- positive, negative, nonlinear, and static trajectories.

Collect independent human labels for `has_arc` and the four dimension scores.
Report:

- agreement on the binary decision (Cohen's kappa or Krippendorff's alpha);
- dimension and overall Pearson/Spearman correlations;
- mean absolute difference from human scores;
- cross-judge replication with at least one second LLM family;
- confusion matrix for `present / absent / uncertain`.

Run targeted negative controls:

| Perturbation | Expected behavior |
| --- | --- |
| Replace a cited quote with an unrelated quote | evidence grounding drops |
| Shuffle phase order | `trajectory_coherence` drops |
| Repeat one phase position across phases | action/reasoning progression and trajectory drop |
| Insert an unexplained personality reversal | entailment/coherence drop |
| Convert a true arc into a static vignette | presence should turn negative |

Failing a sensitivity test means the metric is measuring plausibility or
writing quality rather than arc presence.

## 7. Report the result

For every generator-condition pair, publish:

- story and character counts;
- extraction coverage and invalid-evidence rate;
- character/story arc rates;
- mean best-axis score;
- all four dimension means;
- paired confidence intervals;
- an audit file identifying representative true positives, false positives,
  and missed arcs.

The final claim should distinguish two levels:

1. **Presence:** does at least one principal character show a supported arc?
2. **Breadth and quality:** how many principal characters do so, and how
   coherent is the best-supported trajectory?

This distinction is the direct narrative-generation adaptation of ArcANE's
phase-level scores and trajectory-level PTF.
